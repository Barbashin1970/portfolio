# CLAUDE.md — сайт-портфолио Олега Барбашина (portfolio)

Персональный сайт-портфолио: «Системный аналитик и разработчик ИИ-систем: от идеи и ТЗ
до работающего прототипа». Цель: посетитель за 10 секунд понимает, что перед ним
мастер, и хочет заказать сайт или ИИ-решение.

**Состояние на 2026-10-27:** фазы 1 и 2 закрыты (разборы [фазы 1](docs/FAZA-1-RAZBOR.md)
и [фазы 2](docs/FAZA-2-RAZBOR.md)) — первый экран с живым графом, избранное с пином,
каталог по отраслям, контакт и футер. После фазы 2 (2026-10-27, [разбор](docs/VITRINA-RAZBOR.md)):
избранных шесть, игры — своя секция, safety снят — на витрине 30 проектов. Сайт
выкатывается на Pages с фазы 1 (Р-23). Дальше — фаза 3: EN, SEO, Lighthouse. Первая
версия — только портфолио (Р-15).

## Как работаем

- Порядок — навык `skicoding`: разбор до кода; шаг не закончен, пока не обновлены
  задетые документы; отложенное записывается в `docs/BEKLOG.md` с причиной и признаком
  «когда пора».
- Фазы: 0 — данные и план → 1 — каркас и hero → 2 — карточки проектов, контакт →
  3 — EN, SEO, Lighthouse, проверка живого сайта. Выкатка на Pages — с фазы 1 (Р-23).
  Резюме и отложенные секции — следующий план. Следующая фаза начинается только
  после «ок» Олега.
- Перед коммитом — `npm run check` и `npm run check:private`; файлы добавляются
  поимённо, без `git add .`. Пуш в `main` выкатывает сайт.
- После каждой фазы — сборка, линтер, проверка типов, тесты и короткий отчёт: что
  сделано, что дальше.
- Число в документе или на сайте идёт вместе с командой, которой получено.
  Ненаписанное называем ненаписанным.

## Договорённости — не нарушать

Из брифа, с уточнениями Олега от 2026-10-26.

1. **Показываем все проекты, приватные тоже** — с описанием, стеком и скриншотами
   публичных экранов демо (Олег, 2026-10-26). Ссылки на код приватного репозитория нет:
   в типах `repoUrl?: never`. Скриншотов кода нет.
2. **Репозиторий сайта открытый.** В отслеживаемые файлы не попадают личная
   инфраструктура, внутренние адреса и сырые записи. Всё это лежит в `.private/`.
3. **Нерабочие демо не публикуем.** Адреса проверяются перед публикацией.
4. **Ничего не выдумываем.** Цифры — из GitHub и пояснений Олега. Отзывы и логотипы —
   только подтверждённые.
5. **Анимационный бюджет:**
   - один сильный эффект на секцию;
   - easing и длительности — только из `src/motion/tokens.ts`;
   - анимируем только transform и opacity;
   - один WebGL-фон, и только в hero;
   - очистка через `useGSAP`.
6. **`prefers-reduced-motion`:** без Lenis, без пина, без WebGL.
7. **Телефоны:** без пин-горизонтали и без тяжёлого фона.
8. **Lenis — единственное сглаживание.** Синхронизация с GSAP ровно как в брифе
   (`lenis.on('scroll', ScrollTrigger.update)`, `gsap.ticker.add`, `lagSmoothing(0)`).
   После изменений вёрстки — `ScrollTrigger.refresh()`.
9. **Качество:**
   - Lighthouse на мобильном профиле: Performance ≥ 90, Accessibility ≥ 95;
   - семантика, фокус, контраст AA, alt;
   - SEO: title, description, Open Graph, JSON-LD Person, sitemap.
10. **Языки и тексты:** RU по умолчанию, EN вторым. Тексты живые и конкретные, без
    канцелярита. Заголовки предлагаем мы, правит Олег.
11. **Стек:** Vite + React + TS + Tailwind + shadcn/ui; GSAP + ScrollTrigger
    (`@gsap/react`); Lenis; React Bits (копии в `src/components/fx`, с их `LICENSE`).
12. **Публикация — GitHub Pages через Actions, как у PROMPT-Professor.** Не Vercel из
    брифа: так решил Олег 2026-10-26.
13. **Контакты — Telegram и e-mail.** Формы нет: письмо открывается ссылкой `mailto:`
    с темой и заготовкой, адрес написан буквами.

## Чего сайт не делает

- не рекламирует n8n, Node-RED и OWL — ни на сайте, ни в README: доказательств в проектах
  пока нет (Олег, 2026-10-27);
- нет бэкенда, базы, авторизации, аналитики с cookie;
- нет формы заявки и любого сбора данных: контакты — Telegram и почта;
- в первой версии нет резюме, цифр, услуг, таймлайна, стека и «Доверия»;
- нет блога, CMS и FAQ;
- нет выдуманных цифр, отзывов и логотипов;
- нет ссылок на код приватных репозиториев и скриншотов кода;
- нет второй анимационной библиотеки и второго сглаживания поверх Lenis;
- нет WebGL на телефонах.

## Команды

Сначала `nvm use` (Node 22 из `.nvmrc`).

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер: http://localhost:5173/portfolio/ |
| `npm run build` | клиент + серверная сборка + предсборка `dist/client/index.html` |
| `npm run preview` | собранный сайт локально |
| `npm run lint` · `typecheck` · `test` | ESLint 10 · TypeScript 6 · Vitest 5 |
| `npm run check:dist` | страница сверяется со словарём, заглушек нет во всём `dist/` |
| `npm run check:layout` | вёрстка в Chrome: 320, 375, 1440 px и reduced-motion; пин, фильтр, видео, лента избранного, переход к «Контакту»; `-- --shots DIR` — скриншоты |
| `node scripts/capture-shots.mjs [slug…]` | скриншоты демо в `public/media/` — WebP |
| `node scripts/encode-video.mjs <файл> <slug> [--portrait] [--crop-top N \| --crop W:H:X:Y] [--seconds S \| --keep A-B,…] [--blur X:Y:W:H@A-B,…]` | видео карточки: обрезка кадра, нужные отрезки, размытие области на время показа; ffmpeg — из `FFMPEG_PATH` |
| `npm run check:private` | внутренние строки не уходят в git и `dist/` — только на ноутбуке |
| `npm run check` | всё, кроме `check:private` |

## Уроки и навыки vault'а, которые здесь действуют

Уроки — в `knowledge/lessons/` vault'а, навыки — в `knowledge/skills/`.

- Публикация: навык `publish-github-pages` — регистр имени репозитория, `base`,
  `.nojekyll`, текущие версии действий, опись перед открытием репозитория.
- Приватность: `private-repo-made-public-leaks-history`.
- Контакты: `forma-vs-otkrytaya-pochta` — почему формы нет и как устроить `mailto:`;
  `email-obfuscation-that-isnt` — почему адрес не прячем.
- Языки: `browser-translator-breaks-react-dom`.
- Якоря и пин: `accordion-scroll-lands-on-wrong-section` — проверяем переход
  к нижней секции, а не к первой.
- Адреса: `spa-catchall-rewrite-is-a-soft-404` — мусорный адрес обязан отвечать 404.
- Проверка ссылок: `python-org-macos-urllib-no-root-certificates` — в сценариях curl
  или Node fetch, не urllib.
- Заглушки: `html-guard-misses-placeholders-in-downloadable-files` — сторож ищет
  «[ФИО]», «[ник]» и подобные заглушки во всём `dist/`.
- Инструменты для проверок вёрстки: headless Chrome на macOS не сужает окно меньше
  500 px. Мобильную ширину проверяем через iframe шириной 375 px или эмуляцию устройства.
